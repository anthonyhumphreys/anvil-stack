The mobile companion should stop explaining Anvil and become a control surface.

Principles:
- The first screen answers: what is running, what needs me, what can I do now?
- Copy should be labels, status, and consequences, not product pitch.
- Mobile is not a mini IDE. It is a remote steering wheel for local work.
- Approvals are safety decisions. They need hierarchy, friction, and clear consequences.
- Chats are live threads, not marketing prompts.
- Settings is pairing and host selection, not onboarding copy.
- Visual quality should come from density, typography, state, and polish, not more cards.

Screen direction:
- Work: turn into an operations board with active run summary, queue, and one focused launcher.
- Approvals: make each decision scannable: action, scope, risk, consequence, then approve/decline.
- Chats: emphasize active sessions and recent thread content; remove “start from anywhere” tone.
- Settings: tighten into host management and pairing utilities.
- Shared UI: stronger primitives for rows, status bars, command blocks, and action clusters.
