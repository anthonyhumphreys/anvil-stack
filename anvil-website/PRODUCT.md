# Anvil website product context

The website explains four open source Anvil surfaces without blurring their boundaries: Desktop coordinates local delivery work, Registry controls npm dependency ingress, Node Base constrains install execution, and Cloud defines inspectable runtime contracts.

The primary audience is a developer or technical lead deciding which surface applies to their task. Maintainers and contributors need the same site to act as a dependable map into architecture, setup, reference material, status, and repository ownership.

The site should earn trust through concrete proof: real screenshots, commands, package and repository names, explicit ownership, current status, and stated limits. It should not imply that an agent, heuristic, or alpha component provides stronger guarantees than the implementation does.

The main actions are to choose a product, search the documentation, follow a Learn, Build, or Reference path, inspect the source, and download Anvil Desktop.
